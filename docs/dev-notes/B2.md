## Decisions (for DECISIONS.md, please confirm)
- Sync import limit **50 valid rows**, not 1 000: bcrypt-12 measured 178 ms/row in the dev container; prod PHP `max_execution_time` 30 s and
  nginx 60 s would cut a synchronous 1 000-row commit (~3 min). Dry run stays synchronous for every size (no hashing, max 3 000 rows).
- Queued import = slices (100 rows/job, ~20 s) so the single worker keeps sending OTP mail and stays under `retry_after` 90 s; a failed slice
  leaves the created students (each slice is one transaction; uploading the same file again continues where it stopped).
- Hash chain in a side table sealed after commit instead of columns on activity_log written in the insert: same detection, no global lock,
  activity_log stays INSERT/SELECT only. Plain SHA-256 as SECURITY §3m-9 says (HMAC with a separate key would also stop a DB-only attacker).
- Spreadsheet of a queued import is deleted when the job ends (SECURITY §3f says "after 7 days").
- 'unsafe-eval' removed unconditionally (not tied to `csp_safe` any more).
